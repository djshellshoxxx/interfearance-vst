## 2. Scientific basis and limits

The model is **research-informed, empirically calibratable**, not a component-accurate SPICE simulation. Connector studies describe gradual resistance changes under fretting with rapid intermittent excursions; represent persistent condition plus short contact events. The AES guitar-cable study finds cable capacitance alters a passive magnetic pickup circuit; do not apply this response indiscriminately to buffered line sources. Potentiometer behavior depends on taper and circuit, so model wiper position separately from scratch. Research on digitally controlled no-input mixing motivates reproducible stored and sequenced gestures without removing local unpredictability. Nonlinear DSP and sharp switching require antialiasing. These sources support model structure; their papers do **not** establish universal measured values for contact timing, pop spectra, skin impedance, or particular jacks. Treat numerical defaults as listening-test starting points and document them as tunable, not scientific measurements.

## 3. User-facing operating model

Three use cases share the same sound engines:

1. **Hardware:** an effect inserted on a track. Source defaults are restrained and asynchronous, producing subtle hum, resistive loss, scratch, or occasional fault. FX signal may be absent; noise is only generated by enabled and physically plausible conditions. No forced tempo behavior.
2. **Play:** on a track or instrument channel, MIDI notes, GUI gestures, host automation, or an internal repeatable Gesture Lane disturb the modeled hardware. Beat grid schedules *gestures*, while subevents retain physical microtiming. Dry/wet and event intensity determine how much of the track is disturbed.
3. **Create:** a self-excitation option permits sounds on a silent track; design a one-shot or repeating gesture, audition, choose bars or seconds, render a WAV, and import it into the DAW. The plugin may also simply be recorded or bounced by the host. No feedback from the system audio device is needed.

Labels should describe actions and sounds: `Move Plug`, `Touch`, `Shake Cable`, `Turn Knob`, `Wear`, `Hum`, `Pop`, `Density`, `Output`. Advanced engineering controls may be hidden in an expandable Details panel. An existing visual style spec controls visual aesthetics; this spec controls layout, illustrations, states, and interaction only.

## 4. Unified physical/state model

Process sample rate `Fs` from the host. Use a fixed-point or double-precision continuous timeline and sample-accurate transitions inside a block. Parameter smoothing is separate from fast physical contact switching. Reset on sample-rate changes and explicit reset; avoid accidental state reset on normal block changes. Build a shared `MotionDriver` which outputs a normalized position `q(t)`, signed velocity `v(t)`, and acceleration estimate from GUI/MIDI/automation/gesture lane plus bounded correlated micro-motion. Do not equate a static high movement knob with random independent crackles: events follow motion and local wear. Feed the same gesture clock to enabled source models but let them have separate physical parameters, state, and independent random streams. Expose source-specific gesture depth and an explicit option to couple motion; no forced coupling between unrelated objects.

Each source outputs an `inline transform` on its input plus a separately identified `injected electrical/noise` bus. Define processing in physical order: preconditioned input -> module A inline circuit/contact -> module A injection -> module B inline circuit/contact -> module B injection -> optional bounded saturation/output -> dry/wet. The order is user-swappable and audible; bypassed module is exact identity with silent injection. `Wet-only` contains only the transformed signal and generated source, while `Noise-only` monitoring provides isolated injected artifacts for sound design. In source mode, an internal excitation signal feeds the same chain; its absence with an open circuit must not magically create a strong continuous output. Mix at equal input/output compensation where reasonable; implement true bypass cleanly, with latency-consistent output. Document that two effects in series can yield new interactions but do not claim a physically accurate single combined device for every pair.

Suggested contact process: define a slowly varying health `h ∈ [0,1]`, a fixed seeded roughness/wear map `W(q)`, and a contact conductance `g(t) ∈ [0,1]`. The commanded position and pressure set a baseline `g0`; velocity near damaged patches increases the hazard of short resistive excursions and opens. Use a small semi-Markov state machine `GOOD -> RESISTIVE -> OPEN -> RECOVER` with state-dependent dwell distributions, hysteresis, and hard maximum rates. Sample event proposals deterministically from elapsed sample/event position and a source-specific seeded PRNG. Use smooth bounded correlated roughness, not independent white random values per audio sample. Good-to-open and recover times remain short when appropriate, but transitions should use antialiased or bandlimited steps to avoid accidental digital clicks. Genuine sharp physical transients are generated explicitly in the pop model. Parameters `Wear`, `Pressure`, `Position`, `Motion`, `Intermittency`, and `Recovery` should each have a distinct audible role; avoid mathematically redundant knobs. Clamp all energy and event counts.

Electrical injection: compute a connection-dependent admittance/mix between intended signal, high-impedance exposed input, and interference. Model mains as 50 or 60 Hz fundamental with limited harmonics, phase-continuous across blocks; `Hum` determines it, and `Shield` attenuates it. Optional interference bands (low buzz and sparse RF-like demodulated chatter) should be independently controlled and off or very low by default. Do not imply RF can be realistically derived from an arbitrary audio buffer without an RF source. Distinct stereo channels share the mechanical contact state with small configurable electrical differences; stereo image remains stable in Hardware mode. Silence + fully healthy connected cable + hum off should remain silent.

Switch/pops: a contact opening or closing can yield a click through abrupt signal modulation, and coupled DC or stored charge can create a transient. Provide optional `Bias/Charge` state that relaxes exponentially and changes according to connection state, injecting a bounded bipolar charge-discharge impulse at a contact event. Make the mechanism sensitive to circuit/input mode and charge control. Do not automatically add the same canned pop to every event. Cap high-frequency energy, DC, and maximum peak. Display and document `Pop` as the level of this optional modeled circuit contribution, separate from clicks caused by actual signal interruption.

Tone/preamp: `Buffered/Line` gives minimal cable-capacitance coloration; `Passive Pickup` uses a documented, simplified RLC-like resonant pickup/load approximation with source impedance and cable capacitance affecting resonance and damping. Expose `Cable Load` only in that mode (or clearly label its minimal line-mode role). No high-gain preamp or clipping unless selected. Optional controlled saturation may approximate overdriven input stages with adjustable input drive and headroom; implement low-alias processing (tested oversampling or an equivalent technique), denormal protection, DC blocking, and predictable latency reporting.

## 5. Source-specific DSP and behavior

### Loose Jack

An analog TS-style tip/sleeve relationship is enough for version 1; avoid suggesting every connector shares identical contact sequencing. `Insert` controls overall engagement and threshold zones; `Wiggle` contributes mechanical movement; `Pressure` and `Wear` set stable versus intermittent connection. A partly inserted or damaged contact can attenuate input, alternate between resistive and open states, and increase exposure to hum. Contact changes gate the actual incoming signal as well as injecting interference. For a short or ground transition, implement a distinct quieting/contact mode rather than always using an open-circuit hum burst. Ensure zero movement at a healthy position produces no spontaneous high-rate failure unless `Intermittency` is deliberately raised. GUI drag on the plug maps to `Insert`, lateral drag/pressure to `Wiggle`; MIDI can trigger a time-bounded wiggle gesture.

### Exposed Plug Touch

Represent a floating/high-impedance exposed signal conductor and a user body/environmental coupling path. `Finger` or `Touch` controls contact area/conductance; `Pressure` controls stability; `Mains` is 50/60 Hz and harmonics; `Body` colors the spectrum; `Shield` reduces pickup. Touch onset/offset may have modest contact chatter and charge click. The result should include hum/buzz changes that respond causally to touch, not a constant noise file. Add `Circuit Exposure` so this is subtle when properly terminated and stronger when genuinely exposed. Clarify this module is an artistic, simplified input-coupling model, not an exact human-body circuit. A mouse press/drag or MIDI pressure maps to touch; release returns toward baseline.

### Cable Handling

Two distinguishable sublayers: `Electrical` simulates conductor/shield intermittency driven by flex angle, strain, and a spatial weak-spot map; `Handling` simulates optional mechanical rub/taps heard only if a pickup/microphonic path is enabled. `Bend` moves through the weak-spot map, `Shake` creates coupled low-frequency movement and event clusters, `Damage` affects electrical faults, and `Mic` controls the physical handling layer. Mechanically induced audio should be generated from gesture-linked friction bursts and resonant taps with varied envelopes, never from arbitrary uniform white noise. A sound cable with zero `Mic` and no electrical damage has little or no audible handling noise. Allow a localized fault with a reproducible bend position so a user can repeatedly 'find' the crackle.

### Dirty Pot

`Turn` sets wiper position; `Taper` selects linear/log behavior for a level pot, or a documented simple tone circuit variant. Scratch comes from time-varying wiper/contact irregularities during movement across seeded worn regions. Stopping the knob should usually stop scratch; an optional severely damaged setting may remain intermittent under vibration. `Dirt` sets roughness and intermittent conductance, `Wear Position` edits the damaged arc, `Scratch` affects event gain, `Circuit` selects Level or Tone. The underlying level/tone transfer still follows the wiper at zero Dirt; the scratch signal should be tied to input content and optional circuit bias, not always produce full-scale noise on digital silence. Do not conflate taper law, input-stage saturation, and dirty-wiper noise. Support automating smooth movement and selecting a fixed worn region to reproduce bursts at a particular knob angle.

## 6. Two-source behavior

Two activation slots, A and B. Any two **different** source types may be loaded. A source can be moved between slots; duplicate source types are out of scope. Selecting a third source opens a clear replace-A/replace-B affordance and never silently drops a source. Each slot has independent enable, level of disturbance, gesture assignment, seed substream, and source-specific settings; globally shared mains phase and signal path are deliberate. A source may process the other source's artifacts because modules are in series. The UI has `Swap Order` and a compact comparison audition. Cross-source `Linked Gesture` can send one movement envelope to both while preserving independent contacts; off by default. Per-source bypass preserves settings, state capture, and MIDI assignments; bypassing for a period should have a documented clock policy (choose advance physical time silently so un-bypass does not replay old events). Test all six pairs in both orders, each alone, and with both bypassed.

## 7. Sound generation, timing, and repeatability

`Excitation` options: Off (normal effect), bounded broadband input noise, filtered low-level buzz, DC/bias impulse excitation, and a test tone for calibration. In Create mode, allow an `Artifacts-only` output so users make samples without feeding audio. The excitation is internal and must pass through the same two-module circuit; make clear that this is a studio source used to reveal faults, not a claim that a disconnected cable produces these sounds unaided.

Gestures: manual continuous drag, momentary trigger, latched position, MIDI note-on/off and velocity, CC/aftertouch where supplied, DAW automation, and a one- or two-bar Gesture Lane with user-editable trigger steps and per-step intensity. Allow lengths 1–16 steps and divisions 1/4 through 1/32 including triplets; one-shot mode can use a single gesture shape. Supply gesture presets `Wiggle`, `Slow Turn`, `Tap`, `Shake`, `Touch and Release`, but the selected source determines how the gesture acts. Scheduler quantizes the gesture **start** only; audio subevents remain governed by the physical model. `Humanize` offsets starts within a bounded fraction of a step and is deterministic with a fixed seed. `Chaos` increases variability only within constrained physical parameters; it does not arbitrarily change physical laws. The lane should be optional, with a visible Off state in Hardware mode.

PRNG: use an explicitly implemented portable generator and stable integer hashing for per-source/per-gesture events, never `random_device` in the audio thread. User-visible `Seed`, `Lock`, and `New Take`. Save seed, wear maps or their derivation, lane and all parameters in plugin state. Compute host-time placement using sample position and tempo/time signature when available; define fallback on missing transport. Partition event generation into absolute time/step indices so repeated playback, different block sizes, host bounce and loop retriggering give the same result at the same host positions after a defined reset. Free-running live gestures may vary only if the user unlocks the seed; make DAW bounce default deterministic. Seek, loop jumps, stop/start, sample-rate switch and offline rendering need explicit state policy and tests. Host automation may arrive with block granularity through JUCE; use smoothing and internal sample-accurate gesture transitions, and document any external-automation resolution limit honestly.

Sample/loop capture: provide in-plugin `Record` of output into a preallocated bounded FIFO drained by worker, and offline `Render` of the internal excitation/gesture path with a cloned DSP state and fixed tempo. User chooses 1–16 bars or 0.1–30 seconds, bit depth PCM 16/24 or float 32, sample rate 44.1/48/96 kHz, mono/stereo, optional short tail and peak normalization with explicit headroom. `Render` creates a WAV at a user-chosen path; perform file IO and oversampled/offline processing off the audio thread. Do not attempt unauthorized host timeline capture or promise DAW drag-and-drop unless implemented and host-tested. Before exporting a silent result, explain that excitation is Off or contacts are healthy. Name exported files predictably, include seed/tempo/source metadata in a sidecar only if privacy-safe and user requested; never overwrite without confirmation. The simplest reliable workflow remains host bounce/record for incoming-track material.

## 9. Expected user workflows and acceptance examples

**Subtle track coloration:** Insert on guitar, select Loose Jack, Hardware, Passive Pickup, set healthy contact with a small worn spot, minimal Hum and occasional Wiggle. Most of the track remains intact; moving Insert to fully seated reduces faults; bypass produces transparent dry signal. Selecting Buffered/Line reduces the modeled cable-load change.

**Authentic dirty knob:** Insert on a synth, choose Dirty Pot/Level, automate Turn across a worn section. The audio level follows knob position and a clustered scratch occurs at the worn arc; holding the knob still stops the scratch under normal Dirt. Switching to Tone changes tone according to modeled control rather than just adjusting scratch EQ.

**Playable rhythm:** On a drum loop, select Loose Jack + Cable Handling. Enter Play, program one wiggle per beat and lighter shakes on offbeats. The gestures land in time; individual microcrackles vary within each gesture. Lock Seed and bounce twice: null-identical or documented deterministic tolerance with the same host state and sample rate.

**Fresh one-shot:** In Create, choose Exposed Plug Touch + Dirty Pot, enable modest internal excitation, record a touch-and-turn gesture, listen in Artifacts-only, render a two-second WAV. After `New Take`, keep timing and control positions but obtain different microevents. The WAV must remain playable in ordinary DAWs.

**Source order:** Dirty Pot followed by Loose Jack means jack dropout interrupts the pot's artifacts; swapping order may alter whether pot scratch continues through jack events. A/B meters and audition make the difference clear. Link gestures if wanted, but retain each source's independent condition.
