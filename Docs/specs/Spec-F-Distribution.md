## D1 — Landing page and audio examples

### Site (static, no JS framework, host on GitHub Pages from `/site`)
Pages: Home (one-sentence value prop, 3 audio players, download), Sounds (gallery), Manual (rendered from `Docs/*.md` with a
tiny Python build), Download (checksums, version, system requirements), Support (e-mail placeholder replaced at launch),
Privacy (copy of `Docs/Privacy.md`: offline, no telemetry), Changelog. Pure HTML+CSS, `<audio controls preload="none">`, no tracking, no cookies,
system fonts, WCAG AA, Lighthouse ≥ 95.
* Build: `site/build.py` (Markdown → HTML via `markdown` lib, template, sitemap, `robots.txt`); CI job `site` publishes on tags.
* Replace all `*.example` placeholders (`COMPANY_WEBSITE`, `COMPANY_EMAIL` in `CMakeLists.txt`, `Branding`, docs) via one
  `tools/branding.json` consumed by CMake and the site build — single source of truth.

### Audio examples (reproducible, no third-party samples)
* Generated by `ifx-render` (F0.1) from synthetic sources (pluck, drum loop, pad, noise) so there is no licensing risk: 24 examples:
  8 sources/environments × (dry, wet), 4 sound-design recipes from `SoundDesign.md`, 4 "in a mix" demos (synth stems made by the
  same generators), plus 4 pack previews (V5).
* `site/examples.yaml` lists `{id, title, preset, input generator, seconds, seed}`; `tools/make_examples.py` renders WAV →
  encodes to MP3 128k + OGG via `ffmpeg` (CI image), normalises to −16 LUFS, writes loudness table; WAV kept as release artifact.
* Each example page states: preset used, what physical fault causes the sound, and the A/B dry/wet pair.

### Acceptance
Site builds offline from the repo; link checker passes; every audio file plays; examples regenerate bit-identically (same seed).

## D2 — Demo build

### Product decisions (recommended; adjust before building)
Separate **compile-time** target `Interference_Demo` (`IFX_DEMO=1`), no activation or network (consistent with Decisions.md: no
licence server, offline users never blocked). Limits chosen to be generous but clear:
* All sound and all four sources work; **offline render and Save-preset disabled**, **user preset folder read-only**; 10 of 27 factory
  presets; MIDI learn limited to 4 mappings; Studio chain limited to Echo + Drive.
* Every 5 minutes of audio running, a 2-second Dry/Wet duck to 30 % (declicked), and a "DEMO" badge in the header and window title.
* Plug-in name "Interference Demo", **same plugin/manufacturer codes and state format** so projects saved with the demo load
  in the full version; both installed together: the host shows two entries — document "uninstall the demo after buying".
* Code: `Core/Edition.h` with `constexpr bool kDemo`, `edition::allowRender()` etc.; every limit is one `if` at the UI action or in
  the processor (one duck stage in `ParamPipeline`'s final stage). No obfuscation: it is a convenience gate, not DRM.
* Tests: `demo.limitsEnforced`, `demo.fullBuildUnaffected` (flags off = bit-exact output), `demo.projectLoadsInFull`.

## D5 — AAX (Pro Tools)

Blocked on external parties; this section is the checklist so work starts the day access is granted.
1. Avid developer account + AAX SDK download (free but licensed; EULA forbids redistribution → SDK path via CI secret/local, never committed).
2. CMake: `juce_set_aax_sdk_path(${AAX_SDK_PATH})`, add `AAX` to `IFX_FORMATS` when the path exists (`-DINTERFERENCE_AAX_SDK=…`).
   Plugin manufacturer/product IDs for AAX (`AAX_IDENTIFIER`, category `AAX_ePlugInCategory_Harmonic`... choose `Effect`) set in `juce_add_plugin`.
3. Constraints: no editor resizing beyond host rules (Pro Tools allows resizable only with `AAX_eProperty_...`? verify with SDK docs),
   stereo/mono layouts only (`isBusesLayoutSupported` already); sidechain input mapping as AAX sidechain.
4. Pro Tools requires **PACE/iLok signing** (wraptool) — the signing step is a post-build script with credentials in CI secrets; unsigned
   AAX only loads in Pro Tools Developer builds.
5. Validation: AAX Validator (DSH) pass; manual smoke in Pro Tools Intro/Artist/Developer on Windows.
6. Acceptance: `Interference.aaxplugin` loads in Pro Tools Developer, state round-trips, automation lists all parameters, passes DSH.
